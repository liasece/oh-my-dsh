# OhMyDSH 产品文档

这份文档回答「OhMyDSH 为什么存在、为谁解决什么、哪些事明确不做」。判断一个需求该不该进这个插件、怀疑实现偏离了承诺、或者向别人解释三个功能时看它；改代码看[开发文档](development.md)，装机排障看[运维文档](operations.md)。

## 来源说明

本项目的用户会话语料几乎为空：只有 2026-11-12 的三条反馈，导出时会话短 ID 被截断成 `session-`，无法回指具体会话。除标注「语料」的条目外，本文的产品信息都来自仓库说明与记录：[README](../README.md)、[CHANGELOG](../CHANGELOG.md)、提交 `93ef922` 和当前代码。它们说明的是**仓库作者写下的意图，不是用户会话确认过的需求**；无法核实的判断列在文末「待确认」。

## 一句话定位

把输入框周边的三件小事——按时段换模型路由、回合结束后给几条下一步、空草稿按 ↑ 召回自己发过的话——合成一个 DSH 插件包，一次挂载、一页设置、每项可单独关掉。

## 目标用户与场景

- 长时间在 DSH Desktop / Web 里工作的人：高峰时段想自动走另一条路由，低峰再换回来，不想每次手动切模型。
- 回合结束后一时想不出下一句的人：希望有几条可点的下一步，而不是面对空输入框。
- 反复发送相似指令的人：希望按 ↑ 找回自己上一条消息，而不是翻会话记录复制。
- 现状以作者自用为主：`package.json` 的 `author` 是 `liasece`，插件索引给它的标签是 `chinese-first`，没有外部用户反馈记录。

## 设计理念与取舍

- **合并交付，不合并行为**：三个功能各留自己的配置段、开关和界面入口，关掉一个不影响另外两个（`CHANGELOG.md` 0.1.0）。
- **一个包、一次挂载**：Host 侧只注册一个 Typert 服务 `ohMyDsh`，浏览器侧只 `$mount` 一次，避免三个包各挂一遍、导航里三页设置。
- **一页设置**：三个功能是同一页里的三个板块，板块头就是开关；关掉即折叠，减少「设置藏在哪」的寻找成本（语料 2026-11-12T13:01）。
- **开关即停手**：不是隐藏界面，而是宿主侧也空转——不请求模型、不接管按键、不动模型位。
- **只改模型位，不拦请求**：峰谷动态走 `sessionController.selectModel`；改 `agent/request` 会被宿主判成「step preparation 之后又改路由」而失败。
- **只读旁观者**：候选与历史都不写会话日志、不替用户发消息；历史只读本地日志，不消耗模型额度。
- **字段沿用旧名**：`peakValley` / `candidates` / `history` 三段里的字段与原三个插件一一对应，老配置可以原样搬。

## 能力边界与明确不做

- 只在 DSH Desktop / Web 的客户端槽位里工作；TUI 下没有输入框右侧开关、候选条和设置页。
- 输入历史召回的是发送出去的文本：`@` 引用还原成 `@[标签](dsh-file:…)` 文本，图片和附件不参与。
- 峰谷动态没有「全局默认开」：开关按会话，新会话只在创建时间不早于最近一次动作时继承 `lastToggle`。
- 不改会话内容、不代发消息、不做全局快捷键、不采集使用数据。
- 默认配置装好等于不切换：两段峰时路由与谷时相同，需要用户自己改成另一条。

## 常见误解

- 「输入历史中，似乎没有过滤用户消息，agent 消息似乎会消耗额度」（语料 2026-11-12T13:18）：前半句在当时的实现里成立，现已改成只收 `source.kind === 'user'`，助手、子 Agent 的 `agent-message`、运行时上下文、技能目录、压缩摘要都不进列表（未提交改动，2026-11-14 观察）；后半句是误解——历史只读本地会话日志，不请求模型，真正每回合请求一次模型的是提示词候选，可在设置页关掉。
- 「装好就会自动换路由」：默认两段路由相同，且会话开关默认关，装完什么都不变。
- 「设置里有三页」：那是合并初版；现在导航里只有一页 OhMyDSH。
- 「关掉开关只是隐藏界面」：宿主侧同样停手。

## 产品发展历史

- 2026-11-12 之前：三个功能各自是独立插件 `dsh-peak-valley-model` v0.20.0、`dsh-prompt-candidates` v0.3.1、`dsh-prompt-history` v0.1.0（来源：CHANGELOG 0.1.0、提交 `93ef922`）。
- 2026-11-12：三个插件合并为 `oh-my-dsh` 0.1.0，产品上仍是三个独立能力与开关，交付变成一个包（来源：提交 `93ef922`；合并的分层与代价见[开发文档](development.md#开发历史)）。
- 2026-11-12：三条用户反馈要求胶囊开关、设置收进一页、输入历史只召回用户消息；工作区已实现但未提交（来源：语料 12:50 / 13:01 / 13:18，及未提交的 CHANGELOG 条目）。
